# 基本工作协议

本文件说明日常工作流程；代理执行约定见根目录 `AGENTS.md`。正式源码只在工作区根目录 `personal-homepage/` 维护。

## 1. 修改边界

- **所有说明文档使用中文。** 覆盖 README、维护约定、框架概要、工作协议、模块说明、素材说明和变更记录；文件路径、代码标识、命令、网址及专有名称保留原文。
- **所有网页呈现内容使用英文。** 覆盖正文、导航、按钮、弹窗、提示、空状态、图片署名、页面标题与描述、替代文本和无障碍标签；独立页面如 `credits.html` 同样遵守。
- 页面使用常规字形和适中字号，保持简洁学术风与宇宙主题。
- HTML 管结构，CSS 管样式，`content.js` 管学术与相册数据；不把样式和脚本重新塞入 HTML。
- 保留根目录页面和相对资源路径，保持无需构建即可部署；新的框架、依赖和目录迁移应有具体需求。
- 只填入用户提供的真实资料；占位图片替换时同步替代文本、说明和来源。
- 修改已有文件前读取相关源码与文档；保留用户未提交的改动，按本次任务范围编辑。

## 2. Git 开始与同步

`origin` 为 `https://github.com/PaulLi07/personal-homepage.git`，`main` 跟踪 `origin/main`。

```sh
git status --short --branch
git fetch origin
git log --oneline --left-right main...origin/main
```

工作区干净且本地可以快进时，在 `main` 上执行 `git pull --ff-only`。本仓库已设置 `pull.ff=only`、`push.default=simple` 和 `fetch.prune=true`；不会通过普通 pull 自动产生合并提交。

如果存在未提交改动、远端新变化或分歧，先检查差异并保留双方内容，再处理同步。不要使用硬重置、丢弃工作区或强制推送来覆盖变化。

小范围内容、修正或文档更新可在 `main` 上本地提交。跨模块功能或较大设计调整使用任务分支：

```sh
git switch -c feat/short-topic
```

任务完成并通过检查后再合入本地 `main`。

## 3. 模块扩展与说明

模块指可独立维护的页面分区、详情栏目或功能。每次新增模块、扩展功能或改变模块接口，都必须随代码交付相应的简洁中文说明；纯文字纠错不属于模块扩展。

1. 新模块复制 `docs/modules/TEMPLATE.md` 为 `docs/modules/<模块标识>.md`，并在 `docs/modules/README.md` 登记。
2. 已有模块扩展时更新对应说明；没有独立说明的模块，先补建。文件名使用简短的小写英文标识，文档正文使用中文。
3. 说明保留用途、页面入口、相关文件、数据与依赖、修改或扩展方式，避免复制整段源码。
4. 按下节完成兼容性测试，在同一说明中写明日期、环境、结果和未覆盖项；有故障时修复并复测。
5. 结构变化同步 `docs/ARCHITECTURE.md`，重要变化同步 `CHANGELOG.md`。模块说明与功能一起提交，不留到以后补写。

## 4. 兼容性测试

**每次模块扩展必须实际测试兼容性。** 布局或交互修改也适用。`npm run check` 检查语法、资源与数据映射，不能验证浏览器布局和交互；仅修改说明文档时执行静态与文档检查即可。

| 检查范围 | 最低检查内容 |
|---|---|
| 桌面与手机布局 | 实测桌面及手机宽度，检查窄屏文字、图片、导航、弹窗和横向溢出；例如 1440、390、320 像素宽度，记录实际使用的视口 |
| 浏览器 | 至少在一个可用浏览器实测桌面与手机视口，记录版本；目标覆盖 Chrome / Edge、Firefox、Safari，优先实测可用的 Chromium、Gecko、WebKit 不同内核 |
| 操作方式 | 检查鼠标、键盘 Tab / Enter / Escape、焦点恢复；涉及触屏的功能另测触屏或触摸模拟，并注明是否为模拟 |
| 导航与路径 | 检查模块入口、详情直达哈希、刷新、前进 / 后退及关闭行为；确认 `/personal-homepage/` 子路径下资源与链接可用 |
| 状态与动画 | 按功能检查空数据、图片加载和减少动态效果设置；新代码不得破坏既有设置 |
| 既有模块 | 回归受影响的首页导航、学术详情和生活相册，确认共享样式、数据或脚本未导致退化 |

测试记录必须列出实际环境、检查项、通过或失败、问题与复测结果。没有运行的浏览器、真实设备或状态明确标为“未测试”，并在交付摘要中列出限制；不得把模拟视口写成真机测试，也不得把未覆盖项写成通过或宣称全平台兼容。只测试一种内核时，不得标记“跨浏览器测试通过”。已发现的兼容性故障修复并复测后再完成扩展。

## 5. 检查与提交

```sh
npm run check
git diff --check
git diff
# 示例：仅暂存本次任务涉及的文件
git add README.md docs/WORKFLOW.md
git commit -m "docs: 明确项目工作协议"
git status --short --branch
```

- 提交信息使用 `feat:`、`fix:`、`style:`、`docs:`、`chore:` 加简短说明。
- 每个提交围绕一个目的，暂存前确认文件范围；系统文件、缓存、ZIP 和 Git 元数据不属于网站源码。
- 内容和资源修改检查实际数据与链接，并核对文档中文、网页英文的语言界定。
- 模块扩展核对对应说明及实际兼容性测试记录；布局和交互修改执行上节检查。
- 增加栏目、改变数据结构或工作流程时，更新框架概要与对应说明；重要变更记录在 `CHANGELOG.md`。

## 6. 发布与交付

普通维护完成本地检查和 Git 提交，交付变更摘要、验证结果、提交状态及需要用户补充的资料。只有明确请求发布或推送时才更新远端；本次绑定远端本身不代表发布。

**手动上传：**运行 `npm run package`，解压 `../outputs/personal-homepage-source.zip`，进入解压后的 `personal-homepage/`，将其内部文件与子目录上传到仓库根目录。`.nojekyll` 也是需要保留的根目录文件。

**Git 推送：**在发布请求的范围内，检查 `origin/main` 的最新状态、处理分歧并确认待发布提交，再执行：

```sh
git push origin main
```

推送可能需要用户现有的 GitHub 身份认证。不要将令牌写入远端 URL、配置文件或仓库。Pages 部署完成后，检查线上首页、学术详情、照片和手机布局。

如果通过 GitHub 网页上传了更新，之后先 `git fetch origin` 再比较并同步本地，防止本地与线上形成两份不同的源码。

## 7. 常用维护入口

| 操作 | 命令 / 文件 |
|---|---|
| 本地预览 | `npm run preview`，默认端口 8767 |

| 替换图片 | `assets/images/` 与 `docs/image-sources.md` |
| 项目检查 | `npm run check` |
| 模块说明与测试记录 | `docs/modules/README.md`、`docs/modules/TEMPLATE.md` |
| 打包到指定位置 | `python3 scripts/package.py --output /path/to/site.zip` |
| 查看远端绑定 | `git remote -v` |
| 查看待发布提交 | `git log --oneline origin/main..HEAD` |
